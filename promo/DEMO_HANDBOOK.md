# 展示用デモ手順（まっさらな環境から一周）

ブースで「何も無い状態から、会議 → 議事録 → タスク → チャット → 成果物 → 矛盾の指摘 → 修正 → 完了 → Wiki」を見せるための手順。
他の参加者（山田・田中・佐藤）の操作はコマンドで代行し、**鈴木の画面だけをプロジェクタに映す**。

## 0. 準備（前日 / 開場前）

```bash
cd ~/ai-hack-2026
bash promo/demo_blank.sh start      # 空のサーバーを起動（http://localhost:8790）
```

ブラウザで `http://localhost:8790` を開き、**鈴木**でサインイン。ここでひととおり空を見せる。

| 見せる画面 | 言うこと |
|---|---|
| ダッシュボード | 「検知 0・タスク 0。エージェントはまだ何も見つけていません」 |
| 検知結果 / タスク / チャット / 会議室 / 成果物 / Wiki | 「全部ゼロです。ここから 1 つのプロジェクトを立ち上げます」 |

> 本番（https://agent.leadus-nova.com）を使う場合は空ではなく **架空データ入り**。エージェント画面の「デモをリセット」か
> `curl -s -b cookie -X POST https://agent.leadus-nova.com/api/agent/reset` で初期状態（Finding 15 件）に戻る（LLM は呼ばない・約 1 分）。

---

## 1. プロジェクトの立ち上げ（人が手で入力）

鈴木の画面のチャット `#general` に、**自分で打つ**:

```
商品X（青葉りんごソーダ）の立ち上げを始めます。これからキックオフ会議をやります。
```

言うこと: 「普段どおりチャットに書くだけ。投稿がトリガーでエージェントが動きます」

---

## 2. 会議（議事録とタスクが生まれる）

```bash
bash promo/demo_blank.sh meeting
```

1. 表示された会議室 URL をブラウザで開く（発言 13 件が字幕として入っている）
2. 画面で発言を見せる。特に鈴木の 2 つ:
   - 「初回ロットは300ケースで確定します」
   - 「**第4四半期は450で確定。得意先から増量の要望が来ても、今期の見込みは450から変更しないでください**」← 後で効く
3. ターミナルで **Enter** を押す → 会議終了 → 文字起こし確定 → エージェントが抽出

できるもの:

| 画面 | 結果 |
|---|---|
| 議事録サマリー `/meet/<id>/minutes` | 決定・タスク・懸念。各項目に根拠の発言（原文） |
| タスク `/tasks?view=board` | 3 件が担当つきで登録（山田・田中・佐藤） |
| Wiki | 「2026-09-23 商品X キックオフ」ページが自動作成 |

言うこと: 「人がしたのは終了ボタンだけ。議事録も起票も担当割り当ても書いていません」

---

## 3. 成果物の共有（紐付け）

```bash
bash promo/demo_blank.sh share
```

山田が v1（第4四半期 450）を上げて、チャットにこう投稿する:

```
売上見込表の初版を上げました。会議で決めた 第4四半期 450 で入れています http://localhost:8790/artifacts/file/商品企画/商品X_売上見込.xlsx
```

エージェントの動き:
- URL のファイル名からタスクを推論して紐付け（チャットの発言に「⇢ タスク名」のチップが付く）
- 成果物ライブラリに **v1** として登録（`/artifacts?path=商品企画&view=cards`）
- 「初版を上げました」から **状態更新の提案**（未着手 → 完了）も出る

---

## 4. 決定に反する変更（ここが山場）

```bash
bash promo/demo_blank.sh break
```

山田が v2 を上げる。**第4四半期が 450 → 500**。チャットには理由を書かない:

```
見込表を更新しました http://localhost:8790/artifacts/file/商品企画/商品X_売上見込.xlsx
```

エージェントの動き（20〜40 秒）:
1. 保存を検知して差分を取る（`売上見込!E2 450 → 500`）
2. 関係する決定をコードで絞り込み（商品X・売上見込・第4四半期の語彙）
3. 残った 1 組を Claude Opus が判定 → **矛盾**（confidence 0.85〜0.9）
4. 決定者（鈴木）と変更者（山田）に通知

見せる画面: ダッシュボード（未対応の検知が 1 件）→ 検知結果 `/findings`

| 見せどころ | 言うこと |
|---|---|
| 根拠 3 点（決定の原文・共有の投稿・セル差分） | 「人は誰も『確認して』と頼んでいません」 |
| 判定理由 | 「なぜ矛盾と判断したかが文章で出ます」 |
| 「なぜこれを疑ったか（判定の内訳）」を開く | 「候補をどう絞ったか、LLM を呼ぶ前の処理も見えます」 |

---

## 5. 差し戻しと修正

```bash
bash promo/demo_blank.sh fix
```

鈴木が山田の投稿を**引用して**差し戻し → 山田が v3（450 に戻す）を上げて返信:

```
直しました。会議の数字に戻しています。確認お願いします <URL>
```

エージェントの動き: 修正が決定と一致していることを確認（矛盾は出ない）＋「確認お願いします」から **レビュー中 → 完了** の提案。

---

## 6. 完了と Wiki

```bash
bash promo/demo_blank.sh done
```

鈴木が「確認しました。これで OK です。完了にしてください。」と投稿 → 完了の提案が出る。

画面で **`/findings?kind=status_suggestion` の「適用する」を人が押す**（ここは必ず手で押して見せる）。

| 最後に見せる画面 | 内容 |
|---|---|
| タスク詳細 | 決定 → タスク → チャット → v1 → v2（矛盾）→ v3（修正）→ 完了 が 1 本のタイムライン |
| 成果物の差分 `/artifacts/diff/商品企画/商品X_売上見込_v3.xlsx` | どのセルが誰にいつ変えられたか |
| Wiki「成果物: 商品X_売上見込.xlsx」 | 中身を構造化した本文（概要・表・主な数値）＋版の履歴・変更点・関連する決定 |

締めの言葉: 「人がしたのは、会議で話す・チャットに書く・ファイルを保存する・提案を承認する、の 4 つだけです」

---

## その他のコマンド

```bash
bash promo/demo_blank.sh tick     # 今すぐ巡回して終わるまで待つ
bash promo/demo_blank.sh state    # いまのタスク・検知・Wiki を表示
bash promo/demo_blank.sh stop     # サーバーを止める
bash promo/demo_blank.sh start    # もう一度まっさらから（データは全部消える）
```

## 困ったとき

| 症状 | 対処 |
|---|---|
| 矛盾が出ない | `bash promo/demo_blank.sh tick` をもう一度。LLM の判定には揺れがあるので、出なければ `break` をもう一度実行して v4 を作る |
| 巡回が動かない | 画面右上の「今すぐ巡回」を押す。エージェント画面で自動巡回が ON か確認 |
| 会議が終わらない | ブラウザの会議室タブを閉じてから `meeting` をやり直す |
| 全部やり直したい | `bash promo/demo_blank.sh start`（空に戻る） |

所要時間の目安: 準備 2 分 ／ 1〜6 を通して 8〜10 分。短縮するなら 2（会議）→ 4（矛盾）→ 6（Wiki）だけでも成立する。
