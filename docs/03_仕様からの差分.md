# 仕様書からの差分（実装時の判断）

実装の正本は 01_実装仕様書。以下は実装中に判断して変えた点と理由。

| 項目 | 仕様 | 実装 | 理由 |
| --- | --- | --- | --- |
| 会議の取込 | Google Meet の文字起こしを Drive API で取得 | **自作の会議室 `/meet`** を主経路に追加（ブラウザ録音 → Gemini Files API で話者別に文字起こし → 時刻順統合）。Drive 経路と fixtures も残す | Meet の自動文字起こしは Workspace 有料プランが必要で、ハッカソン期間に確実に用意できない。自作なら「入力は本物」をデモで見せられる |
| 音声文字起こしの LLM | 全 LLM 呼び出しは OrcaRouter 経由 | 文字起こしだけ Gemini API を直接呼ぶ（`app/stt.py`）。コストは `tier=stt` で cost_logs に記録 | 音声入力は OrcaRouter の対象外の想定。判断系（抽出・紐付け・矛盾判定）は全て OrcaRouter |
| 成果物の紐付け | `Task.artifacts` にファイル名が入っていればタスク直結 | **チャットに貼られた SPO リンク**からファイル名を取り出し、その発言が紐付いたタスクの成果物として自動登録。さらに `artifact_change` 自体をタスクに紐付け（ファイル名 → 変更者の担当 → 埋め込み） | 自動生成タスクには artifacts が入らず、統合グラフが繋がらなかった |
| 候補絞り込み | タスク直結があれば埋め込み検索を省く | 直結候補を先頭に置きつつ埋め込み検索も併用（id で重複除去） | `created_from` は task_hint を指すため、直結だけでは「据え置き」のような決定を拾えない |
| 決定→タスクの関連 | （記述なし） | 同じ抽出バッチ内で最も近い決定を `follows` で紐付け（埋め込みのみ・LLM 不使用） | タイムラインと「決定者への通知」に決定が要る |
| 引用の検証 | `verify_quote(item, chunk)` | マスク後のテキスト同士で照合してから unmask | LLM が見たのはマスク後の文なので、原文と照合すると人名を含む引用が全て落ちる |
| 処理済みの管理 | 「未処理フラグ」 | `processed(stage, key)` テーブル（extract / link / detect） | 3段階で別々に増分処理する |
| 依存 | 9 パッケージ | `python-multipart` を追加 | FastAPI のフォーム受信に必須 |
| 議事録 fixtures | 各 300〜600 行 | 各 66〜73 行（3本） | 抽出精度が出てから増量する |
| 候補絞り込みの語彙ゲート | 埋め込み類似度 top-k | top-k のうち、変更の対象語（商品名・列名・シート名）を含む決定だけを候補にする | gemini-embedding は無関係な文同士でも 0.7 超になり、閾値だけでは orphan_change が一度も発火しなかった |
| 判定の文脈 | 決定・変更・タスクに紐付く会話 | さらに「その後の関連する決定」と、変更に意味的に近いチャット発言（＋直後の返答）を添える | 「1200 に戻す」のような取り消し変更や、チャットで合意済みの変更を誤検知していた |
| 判定の指針 | 3項目 | 「その後の決定で許可済みは矛盾でない」「対象が別物なら結び付けない」「決定した値に戻す変更は矛盾でない」を追加 | 上と同じ |
| 数式セルの値変化 | （記述なし） | 計算結果の変化（数式セルの value 差分）は判定しない。数式自体の差分は判定する | 合計行が全て「食い違い」候補になり確認キューが埋まる |
| 重複の統合 | quote の一致で重複除去 | 同一会議内の決定、既存タスクと同内容の task_hint を埋め込み類似（0.88 / 0.82）で統合。チャットからはタスクを自動生成しない | 会議末尾の「決定事項の確認」で全部二重になり、タスクが 37 件に膨らんだ |
| 紐付け LLM のタスク参照 | `[{task.id}]` | `[T1]` のような番号で参照して番号→id に戻す | id は実行ごとに変わるため、replay のキャッシュが当たらなかった |
| LLM キャッシュ | llm_cache.json | chat 応答は JSON、埋め込みは npz（float16）に分離 | 埋め込みを JSON にすると 26MB になった |
| 判定の出力 | contradicts / confidence / reason / severity | `same_subject`（決定と変更の対象が同じか）を追加。false なら LLM が contradicts=true と言ってもコードで矛盾扱いしない。候補の「関連する他の決定」も文脈に渡す | Opus が「対象商品が異なる」と自分で述べつつ「変更の根拠が不明」を理由に矛盾と判定していた。評価 7/10・誤検知2 → 9/10・誤検知0 |
| 成果物の種類 | Excel のみ | 任意の種類。docx / pptx / md / txt は段落単位のテキスト差分（`connectors/docs.py`） | 実務の成果物は表計算だけではない |
| 成果物の置き場 | フラットなフォルダ | フォルダ階層・タグ付け・監視フォルダ（OneDrive 代替）・ブラウザ編集（Luckysheet） | SharePoint のドキュメントライブラリ相当の体験にするため |
| 会議 | 録音のみ | WebRTC のビデオ会議（映像・画面共有・会議内チャット）＋各自の録音 | 「会議ルーム」として成立させるため |
