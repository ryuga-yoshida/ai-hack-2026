# 仕様書からの差分（実装時の判断）

実装の正本は 01_実装仕様書。以下は実装中に判断して変えた点と理由。

| 項目 | 仕様 | 実装 | 理由 |
| --- | --- | --- | --- |
| 会議の取込 | Google Meet の文字起こしを Drive API で取得 | **自作の会議室 `/meet`** を主経路に追加（ブラウザ録音 → Gemini Files API で話者別に文字起こし → 時刻順統合）。Drive 経路と fixtures も残す | Meet の自動文字起こしは Workspace 有料プランが必要で、ハッカソン期間に確実に用意できない。自作なら「入力は本物」をデモで見せられる |
| 音声文字起こしの LLM | 全 LLM 呼び出しは OrcaRouter 経由 | 文字起こしだけ Gemini API を直接呼ぶ（`app/stt.py`）。コストは `tier=stt` で cost_logs に記録 | 音声入力は OrcaRouter の対象外の想定。判断系（抽出・紐付け・矛盾判定）は全て OrcaRouter |
| 成果物の紐付け | `Task.artifacts` にファイル名が入っていればタスク直結 | **チャットに貼られた SPO リンク**からファイル名を取り出し、その発言が紐付いたタスクの成果物として自動登録。さらに `artifact_change` 自体をタスクに紐付け（ファイル名 → 変更者の担当 → 埋め込み） | 自動生成タスクには artifacts が入らず、統合グラフが繋がらなかった |
| 候補絞り込み | タスク直結があれば埋め込み検索を省く | 直結候補を先頭に置きつつ埋め込み検索も併用（id で重複除去） | `created_from` は task_hint を指すため、直結だけでは「据え置き」のような決定を拾えない |
| 決定→タスクの関連 | （記述なし） | 同じ抽出バッチ内で最も近い決定を `follows` で紐付け（埋め込みのみ・LLM 不使用） | タイムラインと「決定者への通知」に決定が要る |
| 引用の検証 | `verify_quote(item, chunk)` | マスク後のテキスト同士で照合してから unmask | LLM が見たのはマスク後の文なので、原文と照合すると人名を含む引用が全て落ちる |
| 処理済みの管理 | 「未処理フラグ」 | `processed(stage, key)` テーブル（extract / link / detect） | 3段階で別々に増分処理する |
| 依存 | 9 パッケージ | `python-multipart` を追加 | FastAPI のフォーム受信に必須 |
| 議事録 fixtures | 各 300〜600 行 | 各 66〜73 行（3本） | 抽出精度が出てから増量する |
