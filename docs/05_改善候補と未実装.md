## 残っているもの（優先度順）

### A. 展示・審査に効く

1. **ループ動画** — 絵コンテ（docs/12）どおり録画するだけ。ブースで一番効く
2. **README の冒頭に GIF**（保存 → 8秒 → 通知）。審査員がリポジトリを開いて最初に見る
3. **数式だけの変更の検知**（評価の見逃し1）— 数式差分を判定対象に含める。判定プロンプトを変えるので `replay --record` が要る（$0.3）
4. **議事録の増量**（各 300 行級）— 抽出精度の主張を強くする。同じく record が要る

### B. 既存 SaaS にあって、まだ無いもの

| 領域 | 無いもの | 難度 |

| 共通 | SSO（Entra ID）、ダークモード、多言語、アクセシビリティ（フォーカス管理・ARIA） | 中〜高 |
| チャット | 既読表示、ファイルのインライン表示（画像プレビュー）、リンクプレビュー（外部）、音声メッセージ、スケジュール送信、メッセージの転送 | 低〜中 |
| メール | 本物のメールボックス同期（IMAP/Graph）、署名、迷惑メール、ラベル、検索演算子 | 中 |
| 予定表 | 他人の予定表の重ね表示、会議室リソース、タイムゾーン、iCal 書き出し、招待メールの自動送信 | 中 |
| 会議室 | ブレイクアウト、バーチャル背景、TURN サーバー（NAT 越え）、サーバー側の合成録画 | 高 |
| Wiki | WYSIWYG のまま同時編集（今は Markdown モードのみ）、ページ権限、添付ファイル、購読通知 | 中 |
| 成果物 | Office 文書のブラウザ表示（docx/pptx のレンダリング）、同時編集、共有リンクの権限、チェックアウト | 高 |

| エージェント | 複数ワークスペース、判定プロンプトの UI 編集、A/B での閾値比較 | 中 |

### C. 品質・運用

- テスト: いまは TestClient のスモークのみ。判定ロジックは評価セットで守られているが、UI の回帰テストは無い
- 単一プロセス・SQLite。数十人規模まで。Postgres 化は `db.py` の差し替えで可能だが未着手
- 巡回スレッドとリクエストの同時書き込みは WAL で解消したが、長時間運用の検証はしていない
- ログの肥大（agent_logs / cost_logs のローテーション無し）

## 判断メモ

- ダークモードは Tailwind の `dark:` を全テンプレートに足す作業量に対して、審査での効き目が薄いので見送り
- 本物の Microsoft 連携（Graph）は Azure のアプリ登録が要る。デモで「アダプタ差し替え」を見せる方が確実
- Luckysheet の日本語化は本家に ja ロケールが無い。英語 UI のまま
